How the 24-hour rule works

It is not a UI trick. Expiry is enforced in four independent layers, all the way down to the disk.

  1. 1

    Stamped on write

    Every message row gets expires_at set to 24 hours ahead by the database itself.

  2. 2

    Filtered on read

    Every query filters expired rows, so an old message can never reappear — even before cleanup runs.

  3. 3

    Erased from disk

    A job every five minutes unlinks the actual image and video files, then deletes the rows.

  4. 4

    Counted down live

    Each bubble shows its own timer, turning amber then red, and fades away on screen when it hits zero.
